## いちばんよく使う操作：弁護士費用を変える

編集するのは **`src/data/fees.yaml` の1ファイルだけ**です。

```yaml
- id: isan-bunkatsu-kosho
  name: 遺産分割（交渉）
  retainer:   { type: fixed, amount: 300000 }   # ← ここを直す
  successFee: { type: percent, rate: 0.10, base: 取得した経済的利益 }
```

料金ページ・各分野ページ・FAQ など、金額を表示しているすべての箇所が
このファイルを参照して描画されます。**ページ側に金額は一切書かれていません。**
したがって「ページによって金額が違う」状態は起こりません。全ページを
人の目で突き合わせる作業は不要です。

### 金額は必ず「税抜」で書く

`amount` と `rate` は**税抜**で記入します。税込表示は `taxRate` から
自動計算されます。

- `amount: 300000` → 画面には `330,000円（税込）`
- `rate: 0.10` → 画面には `11%（税込）`

消費税率が変わったときは `taxRate` の1行を直すだけで全ページに反映されます。
「税込・税別の表記がページによって違う」という事故も構造上起きません。

### 間違った入力は公開できません

以下はすべて**ビルドが失敗して公開が止まります**。人のチェックに頼りません。

| 誤り | 結果 |
|---|---|
| 料率を `0.10` ではなく `10` と書いた | エラー「料率は小数で記入してください」 |
| `id` が重複している | エラー「参照先が一意に定まらなくなります」 |
| 存在しない料金 `id` をページから参照している | エラー＋利用可能な id 一覧を表示 |
| 段階制の区分が小さい順に並んでいない | エラー |
| 金額に小数や負の数を書いた | エラー |
| ページに title / description を書き忘れた | 型エラー |

## 更新の手順（Git を使わない方法）

1. GitHub でこのリポジトリを開く
2. `src/data/fees.yaml` をクリック → 鉛筆アイコンで編集
3. 数字を直して「Commit changes」

これだけで自動的にビルドが走り、問題がなければ数十秒で本番に反映されます。
**入力に誤りがあればビルドが失敗し、本番は古いままで保護されます。**

## ファイル構成

| 場所 | 中身 |
|---|---|
| `src/data/fees.yaml` | **弁護士費用の唯一の情報源** |
| `src/data/firm.yaml` | 事務所名・住所・電話・所属弁護士（唯一の情報源） |
| `src/lib/fees.ts` | 料金データの検証と整形。安全装置の本体 |
| `src/lib/firm.ts` | 事務所情報の検証 |
| `src/pages/` | 各ページ。**ファイル名がそのままURLになる** |
| `src/content/news/` | お知らせ・コラム（Markdown、1記事1ファイル） |
| `public/_redirects` | リダイレクト設定 |
| `scripts/legacy-urls.txt` | 現行サイトのURL一覧（移行の正解データ） |
| `scripts/check-urls.mjs` | URL整合性チェック |

### 触ってはいけない設定

`astro.config.mjs` の以下2つは、現行URLと出力URLを一致させるためのものです。
変更すると全ページのURLが変わり、検索評価を失います。

```js
trailingSlash: 'never',
build: { format: 'file' },
```

同様に、以下のファイル名も変更しないでください。

- `src/pages/FAQ.astro` — 現行URLが `/FAQ`（**大文字**）
- `src/pages/privacy_policy.astro` — 現行URLが `/privacy_policy`（**アンダースコア**）

```bash
npm install          # 初回のみ
npm run dev          # http://localhost:4321 で確認しながら編集

node scripts/check-urls.mjs   # 現行URLの取りこぼしがないか検査
```

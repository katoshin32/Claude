# Claude Code ダイナミックフロー設計書

あなたの業務（**ドキュメント作成 / 運用・自動化**）に対して、Claude Code の「動的に組み立てる
ワークフロー（ダイナミックフロー）」をどう設計・活用するかをまとめたものです。
利用環境（**Web/モバイル + CLI**）と期待（**レビュー・品質担保 + 定型作業の自動化**）に最適化しています。

---

## 1. 「ダイナミックフロー」とは（この文脈での定義）

固定的なスクリプト自動化と違い、Claude Code は「目的」を与えると、その場の状況に応じて
ツール（ファイル操作・MCP 連携・サブエージェント）を**動的に選んで実行**します。
これを業務に効かせる鍵は、毎回ゼロから指示するのではなく、**再利用可能な部品**を
リポジトリに用意しておくことです。部品は次の6つ。

| 構成要素 | 役割 | あなたの業務での使いどころ |
|----------|------|----------------------------|
| **CLAUDE.md** | 常に読まれる前提・規約 | 保存先のルール、外向き操作の禁止事項、言語 |
| **スラッシュコマンド** (`.claude/commands/`) | 定型フローの再利用 | 週次レポート、議事録、レビュー、メール整理 |
| **サブエージェント** (`.claude/agents/`) | 専門特化の処理担当 | ドキュメント品質レビュー |
| **フック** (`.claude/settings.json`) | イベント起点の自動実行 | 保存時の整形・通知（任意） |
| **MCP 連携** | 外部サービス操作 | Notion / Gmail / Drive / Calendar / GitHub / Asana |
| **Web / バックグラウンド / 定期セッション** | 起動方法 | 移動中に指示、PR トリガ、定期実行 |

---

## 2. 最重要の前提：Web/モバイルで使うなら「全部リポジトリに置く」

Claude Code on the web（claude.ai/code やモバイル）のセッションは、毎回**リポジトリを
クローンして起動**します。あなたのローカル PC の `~/.claude/`（ユーザー設定）は読まれません。

> **結論**: スラッシュコマンド・サブエージェント・フック・CLAUDE.md・MCP 設定は、
> すべて**プロジェクト配下（`.claude/`）にコミット**しておく必要があります。
> 本リポジトリはその方針で構成済みです。CLI と Web の両方で同じフローが動きます。

| 設定 | Web セッションで反映されるか |
|------|------------------------------|
| プロジェクト `.claude/`（コミット済み） | ✅ される |
| ユーザー `~/.claude/`（ローカルのみ） | ❌ されない |

## 3. あなたの業務へのマッピング

### A. 定型作業の自動化

| 業務 | フロー | 起動 |
|------|--------|------|
| 週次の活動まとめ | `/weekly-report` → Calendar+Gmail+GitHub+Asana を集計 → Notion 保存 | 定期セッション or 手動 |
| 議事録作成 | `/meeting-notes` → 生メモを構造化 → Notion 保存 + Asana タスク候補提示 | 会議直後に手動 |
| メール整理 | `/inbox-triage` → 分類・ラベル付け・返信下書き（送信しない） | 朝/夕に手動 or 定期 |

### B. レビュー・品質担保

| 業務 | フロー | 起動 |
|------|--------|------|
| ドキュメント品質チェック | `/doc-review` → `doc-reviewer` サブエージェントが5観点でレビュー | 公開前に手動 |
| コード/PR レビュー | 組み込みの `/code-review` skill、または PR アクティビティ購読で自動対応 | PR 作成時 |

## 4. 具体的なフロー詳細

### フロー1: 週次レポート自動生成（`/weekly-report`）
- **トリガ**: 毎週金曜の定期セッション、または手動。
- **処理**: 直近7日の予定（Calendar）・重要メール（Gmail）・PR/Issue（GitHub）・
  タスク進捗（Asana）を集計し、「やったこと/進行中/来週/共有事項」に整形。
- **出力**: Notion に「週次レポート YYYY-MM-DD」として保存し URL を報告。
- **安全装置**: 外部送信はしない。不確かな点は「要確認」と明記。

### フロー2: 議事録の構造化（`/meeting-notes`）
- **入力**: 貼り付けた生メモ、または Drive 上のファイル。
- **出力**: 決定事項・ToDo・論点に整理して Notion 保存。アクションは Asana タスク化を
  **提案**（作成は承認後）。

### フロー3: ドキュメントレビュー（`/doc-review` + `doc-reviewer`）
- **入力**: リポジトリ内パス / Notion ページ / Drive ファイル。
- **出力**: 「該当箇所→問題→修正案」で指摘、重大度順に要約、上位3点を提示。
- 本体は書き換えず提案にとどめる（品質担保を人間の判断とセットにする）。

### フロー4: 受信トレイのトリアージ（`/inbox-triage`）
- **出力**: 4カテゴリ分類 + ラベル付け + 要対応分の**返信下書き**。送信・削除はしない。

---

## 5. 起動方法の選択肢（CLI / Web / 自動）

- **CLI（ターミナル）**: その場で `/weekly-report` のように対話実行。試行錯誤や込み入った作業に最適。
- **Web / モバイル**: 移動中にスマホから「先週分の週次レポートを作って」と指示 → クラウドで実行。
  本リポジトリの設定がそのまま効く。
- **バックグラウンド / 定期実行**: 時間のかかる集計はバックグラウンドで。`/loop` スキルや
  定期セッションで「毎週金曜に週次レポート」のような繰り返しも設定可能。
- **GitHub トリガ**: PR 作成時に自動でレビュー・CI 追従（購読すると CI やレビューコメントに反応）。

---

## 6. 安全・権限の方針（重要）

自動化が外向き・不可逆な操作に及ぶときは、必ず人間の確認を挟みます。本リポジトリの各フローは
この原則で書いています。

- メール: **下書きまで**。送信しない。
- Asana / Notion: 参照と下書き作成は自動、**新規作成・破壊的変更は承認後**。
- カレンダー: 参照のみを既定。予定の追加・削除は明示指示時のみ。
- `.claude/settings.json` で読み取り系を許可し、`git push` 等は確認を挟む設定にしています。

---

## 7. 段階的導入ロードマップ

1. **Step 1（今すぐ）**: 本リポジトリをそのまま使い、`/doc-review` と `/meeting-notes` を試す。
   → 効果がすぐ出て、外部書き込みリスクが小さいものから。
2. **Step 2**: `/weekly-report` を手動で回し、出力フォーマットを自分好みに `commands/` で微調整。
3. **Step 3**: `/inbox-triage` を朝のルーティンに。下書き品質が安定したら対象範囲を広げる。
4. **Step 4**: 週次レポートを定期セッション化、PR レビューを購読で自動化。
5. **Step 5**: 自分の業務語彙・命名規則を CLAUDE.md に追記し、精度を継続的に上げる。

各コマンドは `.claude/commands/*.md` を編集するだけで挙動を調整できます。
まず実運用し、出てきた不満点をコマンドの指示文に反映していくのが最短の改善ループです。
